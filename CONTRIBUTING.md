# Contributing

The best contribution is a small, honest build report. You do not need to have built a production system; you do need to explain what was actually built and learned.

## Submit a project idea

Open an issue or pull request with:

- Title and track
- Difficulty and expected time
- The smallest runnable scope
- Why the project teaches a durable idea
- One likely failure mode
- A stretch path
- At least one source link

Use this template:

```md
### Project title

**Difficulty:** S/M/L/XL · **Stack:** ...

**Build:**

**Why it matters:**

**Stretch:**

**References:**
```

## Quality bar

Avoid entries that are only “build a chatbot,” wrappers around one API with no learning payoff, unverifiable hype, or links without a buildable scope. Prefer narrow systems with visible behavior and a clear way to test them.

## Build reports

When you implement an entry, record the model/provider, approximate cost, time spent, what failed, and what you would change. These reports will become the project's most useful layer over time.
