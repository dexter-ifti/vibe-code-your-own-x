# Roadmap

The goal is to grow from a researched collection into the canonical build-first map for AI-native software.

## Phase 0 — Foundation (complete)

- Establish the point of view and editorial criteria.
- Curate the first build catalog.
- Add landscape and Hall of Fame layers.
- Record research passes and source provenance.

## Phase 1 — Make it browseable (current)

- Maintain [`INDEX.md`](INDEX.md) as the front door.
- Add structured GitHub issue templates and pull-request checks.
- Add metadata to every catalog entry: status, language, time, cost, prerequisites, and verification date.
- Choose and publish a content license.
- Add a link checker and stale-entry report in GitHub Actions.

## Phase 2 — Build the canonical tutorial path

- Implement the agent ladder: loop → tools → permissions → context → graph → memory → evals.
- Give each chapter a clean checkpoint commit and test suite.
- Support at least Python and TypeScript, then add community ports.
- Publish build reports with model, cost, time, failures, and decisions.

## Phase 3 — Community and discovery

- Launch GitHub Pages with search, filters, project cards, and contribution instructions.
- Add “new this week,” “recently verified,” and “retired” views.
- Credit contributors and link to their build reports.
- Invite maintainers of major projects to review their entries.

## Phase 4 — The living frontier map

- Add a weekly or monthly research digest.
- Track model/tool versions without making the catalog depend on one vendor.
- Add benchmark results and reproducibility notes.
- Maintain negative evidence: abandoned, unsafe, misleading, or unrepeatable projects.

## Success criteria

We should consider the project genuinely useful when a newcomer can:

1. Find a project matching their time, language, budget, and curiosity in under two minutes.
2. Start a runnable build in under ten minutes.
3. Understand what the build teaches and how it can be extended.
4. Compare multiple approaches with evidence rather than hype.
5. Submit a project or correction without asking how the repository works.
